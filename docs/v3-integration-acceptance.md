## 3. 本轮发现与修正

1. **P1 Comtrade 空预览语义风险（已修）**：之前空 `data=[]` 可能被解释成正常的「没有贸易记录」。现在显式抛出「没有获得可确认的预览记录」，阻止把样本覆盖缺口误当实际零贸易。新增离线回归。**但外部 Comtrade 接口仍需凭证与分类验证。**
2. **不同验证等级混淆风险（已隔离）**：离线 fixture、真实数据源连接探针和真实市场全链路通过不同脚本、不同工作流执行，报告中分别表述。
3. **跨阶段集成之前未覆盖（已补）**：新增可重复的端到端测试，实际通过 HTTP 查询的接口覆盖行情、事件、贸易、分析和同步健康。
4. **真实市场数据不会提交到 GitHub**：真实行情由短生命周期临时 SQLite 持有，报告仅包含观测数量、范围和状态。完整研究复现实验需在运行环境按来源授权重新获取行情。

## 4. 合并与发布门禁

**当前不得宣告“V3.0 全量生产验收通过”或直接合并全部 PR。** 先完成：

1. 使用真实可用的 Comtrade 账户/授权验证指定商品对应年度的报告国、HS 版本、伙伴国、贸易方向、数量和贸易额；确认可接受的接口频率和响应截断规则。
2. 如希望 EIA API 作为独立来源/灾备接入，用有效 `EIA_API_KEY` 测试；密钥不得写入仓库、PR、日志或公开配置。
3. 对 11 条历史事件作具名人工审核；确认行政生效日与公告日/报道日的区别；修订遵守事件 ID 和原始证据不可静默覆盖要求。
4. 明确对外服务时的 FRED/IMF/世界银行/Comtrade 价格和贸易数据使用、缓存、显示及再分发权限。
5. 进行正式浏览器交互/手机布局验收、最终运行环境的定时任务和失败恢复演练。
6. 完成后按照 PR #1→#6 的顺序，将后续 PR 的目标分支正确调整为 main 或在合并后重新核对差异及完整 CI；这之前不要合并。
